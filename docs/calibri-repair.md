# CALIBRI → LiveCodeBench：来源约束的一轮回修

## 目的和边界

`calibri-lcb-repair-v1` 修复的是解释到图的转换，不是参考程序或题目。
使用一个新的私有 run，原始失败结果、请求和响应不覆盖。
当前只接收已完成 `calibri-lcb-normalize-v2` 中**所有依赖阶段失败题**；
已通过题不重采样，规范化失败和语义审核失败不偷偷纳入本协议。
同一修复结果不能再次送入本协议。得到的是来源约束的派生解释，不是原生 CoT 或官方 gold。

## 三阶段

1. **回修节点**：最多补入八条原题已有的必要前提，必须引用 Q 来源；可以删除真正冗余的节点。
   保留节点的文字、类型、来源与相对顺序不变。禁止改程序、重写推导、
   把新增正确性结论/不变式伪装为 given。没有节点改动也允许只重建边。
2. **重新构边**：不自动复制旧边、不自动连接孤立点；采用原有依赖提示与检查函数。
   每个保留节点必须是答案祖先，这是本项目答案支持图规范，不是一般 DAG 的定义。
3. **新上下文审核**：审完整推理及修改记录，特别检查补入前提是否确实来自题面、
   删除是否丢掉必要信息、依赖是否充分且无虚假闭合边。沿用同一模型，
   不能声称这是独立人工审核。结构闭合不替代语义成立。

必要题面条件必须在图中显式表示，不能验收失败后改成“每步默认可借用全部题面”。
条件的语义相关性仍由审核判断：Python 只能验证来源锚点真实，不能证明引用足以支持命题。

每题只有一轮语义回修；任何阶段失败都保留失败，不直到成功为止反复采样。
传输重试沿用有界基础设施策略，不改变已返回内容；所有尝试计入预算。
`formal_eligible=false`，通过模型审核不自动正式发布。

## 冻结、隐私和预算

- 执行证据、来源、程序及逐测试哈希沿用原执行门槛并重新核验。
- 回修 seed 绑定旧 normalization、旧依赖响应及可复现的拒绝原因。
- 程序生成新编号、精确引文、原/新编号映射、添加/删除记录及前后 SHA256。
- API allowlist 仅含公开题面、原输出、参考程序及图诊断；不发送隐藏测试、凭据或本地路径。
- 原 run 和本 run 消耗累计计入 600 请求 / 2500 万保守预留 token 总额。
  不允许并发准备多个互相不知道预算的分支；单协调者顺序推进后续批次。
- 三题验收配置：worker=2，最多9请求、120万保守预留token，输出上限32768，
  thinking enabled/high。这些是计算配额，不是 API 服务端费用保证。

## 可复现入口

```bash
PYTHONPATH=src python -m dag_builder.calibri_repair \
  --parent /absolute/private/calibri-normalize4-v2 \
  --root /absolute/private/calibri-repair3-v1

PYTHONPATH=src python scripts/run_private_pilot.py \
  --root /absolute/private/calibri-repair3-v1 \
  --config configs/livecodebench-calibri-repair-canary.json \
  --key-file /absolute/private/existing-api-key

PYTHONPATH=src python scripts/audit_calibri_repair.py \
  --root /absolute/private/calibri-repair3-v1
```

程序要求 Python >= 3.10。启动时复制不可变代码和提示快照，结果与源代码版本绑定。
生产调用前应运行完整 unittest 回归；合成测试不执行第三方候选代码，也不调用 API。
真实验收仍使用原三道失败题，不替换题号，不按 PALS 或 g 分数筛选。

## 扩量条件

首先验收原三题，检查 functional 与 stdin 均有可用图，以及是否存在系统性遗漏。
局部仍失败的题保持排除；若暴露系统性规范矛盾，不批量制造相同缺陷。
后续全量仍遵循：冻结候选 → 隔离 CPU 执行 → v2 初次构图 → 对所有合适失败题
一次回修 → 合并来源不重复的接受集 → 发布前审计。所有175题保留流转分母。
没有来源的82题不强行生成；93题是来源候选数量，不是已通过数量。

实现版本 `69d3408`；真实调用9次，308181报告token、832121保守预留token。
运行完整结束，无全局暂停、API合同违规或超预算。历史累计33请求、2059510预留token。

- 3759：补回正数前提，但复杂度可行性仍缺显式n上界，拒绝。
- abc398_c：补回取值和规模约束，但误删了后续打印结论所需的代码输出规则，拒绝。

原通过题abc396_a不重跑，按题号合并累计2/4模型接受，仍非正式发布集。
三题均有完整前后映射、来源和拒绝记录；拒绝题无dag.json，不循环重试。
离线重放核验通过，352项构图库测试与63项PALS测试通过；源码和提示均已冻结。
没有因为图闭合而放过语义缺口，也没有据此宣布“构图质量已保证”。
