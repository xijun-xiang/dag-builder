# 给其他 benchmark 的合作者

沿用 metrics.py 的 g/v/N/D 定义及统一 logprob 证据格式；图算子与模型后端分离，避免在评分代码里硬编码题目。

新增 benchmark 时编写独立 adapter，明确题目、选项、节点、答案的边界；不得把新的 JSON 直接伪装成 GPQA accepted 导出。验证 DAG 无环、原顺序合法、节点唯一、答案隔离。记录真实数据授权与 source hash。

复用 E1 前检查拓扑边是否表示推理依赖、共享节点是否正确，保留合法／破坏共同目标规则。代码通过不代表自动生成的边都是正确的。

复用 E2 前明确固定锚点与祖先前缀规则。不得一边查看 g 一边选择更显著的位置。题目可选多锚点，但必须升级协议、按题聚合，并避免把同题锚点视作独立样本。

更换 tokenizer/template、解析方式、采样设置或评分条件时使用新 protocol/run；不得与当前 GPQA v1 无标记混合。当前 HF 后端没有闭源 API 支持；缺少完整目标 logprob 的模型不能假装适用。

交付时带代码、配置、环境清单、源数据哈希、运行 manifest、统计结果和失败清单；是否分享原题与模型权重由数据授权决定。
