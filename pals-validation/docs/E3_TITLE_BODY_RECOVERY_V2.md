# E3 显式标题＋正文分段与无重复生成续跑

2026-10-07 用户批准修复 Phi 首批格式失败并继续原定实验。

## 唯一科学设置变更

解析版本升级为 `explicit-step-boundaries-v2-title-body`；题目、模型、提示词、
greedy 解码、8192/16384 输出预算、评分 T=1、g/G/M、覆盖率门槛均不变。
原解析器保留为 `parse_v1`，旧部署及旧结果不修改。

Phi 的典型输出是 `<step>步骤标题</step> 解释正文 <step>下一标题…`。
新规则将标题及下一个显式 `<step>`/`<answer>` 前的正文作为同一步，不丢正文、
不按句号新增步骤、不调用 judge。原来有效的轨迹严格保留原跨度。

为保持 token 概率对应真实原文，恢复步骤采用一个连续原文跨度：目标中保留位于
标题与正文之间的原始 `</step>` 分隔符。这些分隔符也计入目标 token 与归一化，
不悄悄删除后拼接非连续文本。使用 `title_and_body_explicit_boundary` 单列标记；
主报告必须补充“排除该恢复格式”的敏感性结果，避免把格式差异解释为推理差异。
删除前一步时删除整段标题＋正文；全/删两侧目标 token 完全相同。

没有明确下一步/答案边界、推理中途截断、标签歧义仍拒绝。仅答案区截断时，
完整过程可评分但答案仍无效。答案提取规则不变。恢复覆盖率不是语义正确率。

## 新运行与证据继承

在新目录初始化三个模型的同一新协议。CPU 导入旧 sealed raw，并将来源文件按
字节复制进 `recovery/source`；源清单哈希绑定新 protocol_id。新协议的派生封装
通过 `recovery_origin` 显式引用旧 protocol、原文件及哈希，不冒充新生成。
原生输出文本、token、prompt、finish_reason 与旧批次不变。

只有完整解析（除版本号外）相同才复用旧分数；其余确定性补评分，不重生成。
答案提取及判分政策相同才复用旧 outcome，安全判分规则不放宽。
旧 attempt/raw/receipt 不齐即拒绝续跑；有不确定生成不能自动重试。

Qwen 全量原始轨迹全部复用，只补计算恢复部分；Phi 首40题复用，只生成原来
未尝试的其余题；Qwen3 旧任务从未运行，按原范围首次生成。
新 run 仍按 Qwen GPU→CPU、Phi GPU→CPU、Qwen3 GPU→CPU 串行，最多8GPU。
Qwen GPU 中不生成任何新轨迹，仅复核与补评分。
正式 allocation 内继续真实 masked-loss、首批/滚动/全量覆盖率门槛，失败即停。

## 验收

- 本地纯 CPU 单测及旧轨迹原文分段重放，包括正例、截断、歧义、导入/拒绝重采样。
- 集群 CPU init 仍进行隔离 selftest、模型文件校验、全量 tokenizer/context 检查；
  再验证完整来源、生成配置相等及导入完成回执，之后才提交 held GPU/CPU 链。
- CPU 最终审计核对原始来源哈希、派生封装、复用分数全部内容、逐 token 算术、
  无效题与全部分母；没有自动覆盖或补造旧审计 PASS。
- 保留旧版本结果作为敏感性/开发记录，最终跨模型比较使用统一新解析版本。
