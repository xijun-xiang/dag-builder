# 两个新增模型的独立部署

单模型运行仅解耦部署，不改变 E3 科学协议。显式使用 `extension-llama3` 或
`extension-internlm3`；manifest 保存 deployment_slot 和实际 model_slots，不能把
其中一份运行冒充完整双模型结果。没有该显式标记时，旧三模型、双模型 cohort
仍要求原有完整模型集合。逐模型配置、输入和 batch 编排与双模型模式相同。

InternLM 在 B1 使用历史已验证的 Transformers 4.47.1 隔离目录；其历史规范
SHA256 固定在 compat_runtime 模块中，计算节点先逐文件重算后才加入 PYTHONPATH。
不安装依赖、不改官方模型代码、不全局降级容器。运行时差异进入配置和数值回执。
新增 b1-code-agent 部署 profile，保持旧 b1 profile 不变；真实 reservation 权限、
节点和资源仍须提交前现场核查，不由 profile 存在推断可立即启动。

所有新部署都重新执行 CPU 架构、上下文与安全检查。GPU 中保留原生 masked-loss、
重复评分和固定首批覆盖率门槛；每模型只生成一次，失败不重试。
2026-10-08 经用户明确批准，取消跨集群合计最多 8 GPU 的操作限制：A1、B1 可独立
推进，每站本任务至多同时使用 8 GPU，两站可各运行一项八卡任务。站内 GPU→CPU
验收依赖和失败取消保持不变；B1 无须等待 A1。此调整仅影响调度，不改变科学协议、
题量、单任务资源或验收门槛，不授权站内重复提交。已部署的冻结源码无需修改。

E1/E2 沿用之前冻结的 DAG 和锚点，与 E3 原题集合不同。context_audit 对全部 E1
full/deleted 加相同目标 token、全部 E2 前缀加既定输出预算进行 CPU 检查；不加载
权重，不截断，不改预算，不排除题目。Llama 的 E3 上下文 cap 不能自动推广为 E2
预算变更。如原生上下文不够，保存具体超限清单，先取得处理协议再运行。

旧模型、失败批次和已有 InternLM E1/E2 全部保留。合表需要独立核验旧证据、冻结输入、
各算子分母、E2 三温共同完整题以及跨运行共同有效题；不通过重采样提高完整率。
