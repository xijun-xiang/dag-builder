## 决策规则：llama-e2-natural-eos-v1

- 原严格协议有效的target、score、逐token证据原样复用。
- 新接纳仅限finish_reason=eos，原始token序列恰在单个真实EOS处结束且未触及预算上限；
  正文非空，无步骤/思考/答案等标签或残片，无代码围栏、标题、列表或多个段落。
- 代码题继续沿用旧is_code_step语法守卫。目标为原始正文strip后的连续span，
  不加闭合标签、不改写内容、不抽取第一句话，不进行正确性或连贯性筛选。
- 正常EOS仅提供操作性边界；规则不能保证逻辑原子性或语义质量。
- 截断、嵌套和结构歧义继续无效。使用原8次重复，N/A不填0；D至少2个有效值才有定义。
- 原prompt、温度0.3/0.7/1.2、种子、模型、Tscore=1、前缀/删除节点、g/N/D保持不变。
  只新增解析规则；GPU不调用generate。

## 执行与效率

CPU prepare先重放旧audit，核对原始token解码、prompt及旧评分输入，完整核验模型哈希，
生成仅新增可评分项的队列。新run/source与旧run独立，旧文件只读。
单次8GPU补分：每卡加载模型一次、真实native masked-loss与重复评分检查后立即领取
共享长任务优先队列；不等首批覆盖率、没有重新生成、没有GPU占用下的代码判分。
CPU audit在GPU释放后核查每项唯一领取/完成、所有逐token算术、原始来源不变和模型哈希。
三个阶段的Slurm科学主/batch/.0及应用证据均通过才能称完成；不因覆盖率低停止或补抽。

输出严格版和恢复版并列：每温有效分母、三温共同完整题、g/N/D及题级bootstrap区间。
两版完整题集合可能不同，差异不能仅归因数值变化；旧严格共同完整题内的旧分数应完全不变。
主张限于可评分子集。已观察数据用于制定规则，必须披露开发适配性质。
