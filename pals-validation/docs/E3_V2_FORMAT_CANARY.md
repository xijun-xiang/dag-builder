# E3 V2 分步格式 canary（开发门槛，非正式结果）

V1 的 Phi-4-mini 固定首批 40 题全部生成并保留，但只有 18 条完整符合 `<step>/<answer>` 语法；GPQA 2/8、HumanEval 1/8、LiveCodeBench 2/8。无效输出通常是标签外文字、Markdown 代码围栏或缺失 `</answer>`，并非达到 8192/16384 token 上限。因此 V1 原始记录不能被修补或重采样冒充有效 E3 结果。

## 唯一改动与问题

V2 对三模型使用同一增强格式提示：在 system 中展示明确的标签骨架，并在 user 问题末尾重复「以 `<step>` 开始、只在标签内写推理、以唯一 `</answer>` 结束、不要代码围栏」。正文问题、答案/测试、模型快照、T=0.7、采样与输出预算、严格解析器、相邻步骤删除的 g 和 G/M/W 定义均不改变。它检验的是**分步格式可用性**，不把提示改变后的结果与 V1 当作同协议配对比较。

## 固定新题与保留旧证据

- V1 首批为各 benchmark 按 `problem_id` 排序的第 1 个 8 题 batch。V2 只取第 2 个 8 题 batch，五组共 40 道新题；三模型题目集合相同，batch seed 仍按既有规则随模型 ID 确定。
- V2 使用全新的代码快照、配置目录和 run 目录，协议 ID 与 V1 不同。V1 的 40 题 raw、失败、评分和审计均不可覆盖；V2 每题每模型只生成一次，started-without-raw 不自动续发。
- 先初始化三个模型并分别完成原生 masked-loss 参考门槛。先仅生成 Phi-4-mini 的 V2 40 题，验收调度终态、5 attempts/raw、40 个唯一 ID、8 shard、结束原因、逐组格式分母与原始哈希。
- 预定工程门槛：Phi 至少 36/40 条完整分步轨迹，且每组至少 6/8；没有 `length` 截断或系统故障。门槛只决定是否继续同协议三模型 canary，不是论文统计显著性检验。任何失败都如实保留并暂停，不反复调提示直到得到漂亮数据。
- Phi 达门槛后，用同一 V2 代码/提示/新题生成 Qwen2.5 与 Qwen3，并分别执行 score、受限 CPU evaluate、离线 audit。无效样本仍进总分母，G/M/W 记 N/A，不填零。
- 本阶段不启动 3732 题全量；是否进入正式 E3，须结合三模型可用率、代码安全门槛及实际资源另行决定。

V2 只验证结构化 CoT 能否稳定取得。即使格式门槛通过，也不能据此证明 PALS 衡量正确性、重复生成稳定性或 CoEvalChain 的因果效果。
