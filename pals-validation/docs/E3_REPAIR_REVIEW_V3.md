# E3 安全修复候选：离线验收，尚未准入续跑

本版本只实现可验证的工程修复与解析候选，不授权重新提交实验。
旧冻结运行目录、raw、attempt、分数和失败记录保持只读。

## 已实现的范围

1. 停止检测仍按同一生成 token 尾部 64 token 识别 `</answer>` 或 EOS，
   不再每一步把整个批次的完整历史从 GPU 复制到 CPU。
   检测顺序、首次停止位置和返回理由不变；不改生成配置或固定批次。
2. 正常解码每 30 秒留下追加式进度记录，含生成步数、已结束题数和耗时，
   不打印题目或轨迹。它是可观测性改进，不是已部署的看门狗；
   如果模型 forward 卡住、回调不再执行，仍须由外部监控识别。
3. 每道题首次满足原停止条件时立即独立封存原始 token、文本、提示及结束理由；
   批次返回时逐项核对提前封存值与最终值相等。长度触顶题在批次返回时封存。
   checkpoint 不自动授予重试或续跑权限；存在不确定 attempt 仍停止。
4. 新增独立的、尚未启用的 v3 解析候选，只识别
   `<step>标题</step>正文</step>` 后接明确的新 `<step>` / `<answer>` 的情况。
   标题和正文取自一个连续原文区间，内部关闭标签保留；不改原文、不补答案、
   不拆普通句子或 Markdown，不回收推理中途截断。

活动入口 `greedy_parse.parse` 及其 v2 版本号未改变，运行配置仍要求原协议。
不得仅更新配置中的版本字符串就把本候选用于正式评分；须先冻结新协议，
接入完整的来源导入、分母和敏感性审计后才可使用。

## 离线回放合同

`scripts/e3_review_repair.py --source MODEL_FOLDER --output NEW_REPORT [--inventory]`

- 比较同一 raw 的 v2/v3 结构，校验 raw 收据；不调用模型或执行候选代码。
- 每条原有效输出必须保持步骤、原文区间、答案解析和状态逐字段一致，
  仅允许解析版本号变化；新恢复格式单列，后续必须报告排除它的敏感性结果。
- `--inventory` 校验原 manifest、批次表、attempt、raw、receipt 并区分：
  已封存、已尝试但中断不确定、尚未尝试。三类合计必须保持原始分母。
- 报告的 `generation_permitted` 仅描述尚未尝试的题；报告始终
  `resume_authorized=false`，不是提交器或接续凭据。
- 结构可评分不等于已有新概率分数，更不等于答案正确。

199 项 CPU 单元测试通过，其中 13 项新增测试覆盖停止检测逐 token 等价、
提前封存、禁止重试、完整性校验、区间无损及拒绝含糊格式。

| InternLM 首批 40 条 | 18 | 18 | 0 |

Qwen2.5 结构有效为 15,883 条；单步轨迹没有步骤配对，不能将它们填为零分。

多数缺少独立答案标记或只用一个步骤包裹全部推理，不能由此候选恢复。
此处不是五模型全量回放：Phi 全量和 Qwen3 原始轨迹尚未完成本候选回放。

## 尚未解决的准入条件

- InternLM 仍只有 18/40 可评分，原覆盖率门槛失败，不能提交相同协议全量。
  将原文编号/标题解释为步骤、将 EOS 解释为过程边界，或更改提示词，
  都是需要单独决定并统一验证的新协议，不属于静默修标签。
- Llama 的 64 条已尝试但没有 raw 的中断记录不得重生成。接续需要新目录、
  来源哈希、显式基础设施 N/A 和完整分母支持；本版本仅给出清单，未实现该接续。
- GPU 实测吞吐和数值回归尚未执行。减少全历史复制不等于已证明提速幅度；
  首批屏障和长输出批次长尾未被本次改动消除，不能宣称调度问题全部解决。
- 旧 GPU/CPU 链与自动跟进不因本提交自动恢复；Llama E1/E2 原前置门槛不绕过。

不得以提高有效率为由补抽样、删掉失败分母、降低覆盖率门槛，
或擅自修改提示、温度、输出预算、重复惩罚、固定批次与评分公式。
