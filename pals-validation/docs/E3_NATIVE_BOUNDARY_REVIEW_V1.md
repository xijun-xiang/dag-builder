# E3 原生编号／标题离线审查（开发性诊断，非新正式解析协议）

入口：`scripts/e3_review_native_boundaries.py --sources SOURCES_JSON --output NEW_JSON`。
来源配置为 `[{"slot":"MODEL_SLOT","folder":"ABSOLUTE_MODEL_FOLDER"}, ...]`。
默认只读各模型原冻结首五批，校验 manifest、批次表、raw 收据、输出顺序及跨模型
同题集合；只有 `--scope all` 才检查给定来源全部批次。不要将缺失原文的局部镜像称为全量。

模块 `e3/native_boundary_review.py` 不接入生产解析器、评分器或提交控制器。
所有产物 `formal_eligible=false`，不授权重新生成、评分或续跑。

## 统一规则

- 已有可评分的多步标签轨迹原样保留。
- 其他输出只检查原文连续 Step N、连续编号、同层 Markdown 标题、独立加粗标题。
  编号重启／缺号单列，不自动串成推理链；代码围栏和显示公式不提供编号边界。
- 候选步骤是连续原文 span；引言并入第一候选段，末尾保留，不凭空增删文本。
- `native_candidates` 只表示存在可形成连续区间的标记，不代表语义步骤质量。
- `candidate_with_existing_process_boundary` 表示候选同时通过已有 v3 过程边界规则；
  `candidate_without_code_mixture` 进一步描述其中没有围栏代码混入的子集。
  后者不是新的代码禁令；两字段必须分开，不能将结构风险当作普遍无效。
- 不猜缺失的答案标签，不修截断，不按句号机械切分，不执行代码、不查标准答案。
